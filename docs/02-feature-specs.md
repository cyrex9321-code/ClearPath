# 02 - Feature Specifications

Acceptance criteria are written as Given/When/Then or checklists and must be testable. Mapping to tests is in [12](12-test-strategy.md). Safety mechanics are specified in [11](11-security-assessment.md) and (from M2) `15-safety-design.md`.

## Part 1 - MVP modules

### A. Dashboard

Real data only. Polls every 2 s **only while the Dashboard is visible**.

| Metric | Source | Behaviour |
|---|---|---|
| CPU | `GetSystemTimes`; usage = 1 - Δidle / Δ(kernel+user) (kernel includes idle); interval measured with `Stopwatch` | First sample shows "Measuring..." |
| RAM | `GlobalMemoryStatusEx` | Used / total |
| Disks | `DriveInfo`, fixed and ready drives only | Used / free / total per drive |
| OS | `CurrentVersion` registry read (ProductName, DisplayVersion, CurrentBuild); build >= 22000 => "Windows 11" | Read-only |
| Last scan / cleanup | SQLite | "No scans yet" when none |
| Recycle Bin | `SHQueryRecycleBin` | Size display only |

Acceptance:
- [ ] Given the Dashboard is first shown, then CPU displays "Measuring..." until a second sample exists.
- [ ] Given a metric API fails, then the tile shows "Unavailable" and a log entry is written; no placeholder number is shown.
- [ ] Given the Dashboard is not visible, then no polling timer is running.
- [ ] CPU value is always within 0-100 (interval math unit-tested with fixed inputs).
- [ ] RAM, CPU and disk values agree with Task Manager within normal sampling variance (manual gate).
- [ ] There is no health score and no fabricated history anywhere.
- [ ] Quick Scan starts the real scanner; Deep Scan is disabled and shows the reason.
- [ ] Given no scans in SQLite, then "No scans yet" is shown.

### B. Quick Clean (junk cleaner) - rules

Explicit allow-list, user-owned locations only. Nothing outside these roots is scanned or touched. No extension-based scanning of arbitrary locations.

| Rule | Root | Filter | Risk note shown before quarantine |
|---|---|---|---|
| User Temp | `%TEMP%` (must resolve under current profile) | Files >= 24 h old | Files in use by running apps are skipped; apps recreate needed temp files |
| DirectX shader cache | `%LOCALAPPDATA%\D3DSCache` | >= 7 d | "Regenerated by games/GPU apps; first launch may be slower" |
| Legacy web cache | `%LOCALAPPDATA%\Microsoft\Windows\INetCache` | >= 7 d | "Cached web content for legacy/IE-mode apps; re-downloaded on demand" |
| App crash dumps | `%LOCALAPPDATA%\CrashDumps` | >= 7 d | Dumps are diagnostic only; removing them loses crash-analysis data |
| Thumbnail cache | `%LOCALAPPDATA%\Microsoft\Windows\Explorer` | `thumbcache_*.db`, `iconcache_*.db`; >= 7 d | Explorer rebuilds thumbnails/icons; folders may render slowly once |
| WER (user) | `%LOCALAPPDATA%\Microsoft\Windows\WER\ReportArchive`, `\ReportQueue` | >= 14 d | Error reports not yet sent or kept for history are removed |

Rules for all categories:
- Every category shows its risk explanation **before** quarantine.
- Individual file selection is always available.
- No category is ever auto-included in permanent deletion.
- ReadOnly, System, and locked/exclusively-inaccessible files are **Skipped with reason**; attributes are never cleared to force cleanup. No rule-specific exceptions in MVP.
- Admin-only categories are visible but disabled.
- Recycle Bin: size display only; never part of any cleanup transaction; emptying is not implemented.

Acceptance:
- [ ] Given a file newer than its rule's minimum age, then it is not listed as eligible.
- [ ] Given a path outside the exact allow-listed roots (including elsewhere under `%LOCALAPPDATA%`/`%APPDATA%`), then it is never scanned or cleaned.
- [ ] Given `%TEMP%` resolves outside the current profile, then the User Temp rule is skipped with a reason.
- [ ] Given a root or any ancestor is a reparse point, then the rule is skipped with a reason.
- [ ] Given a ReadOnly/System/locked file, then it is Skipped with reason and its attributes are unchanged.
- [ ] Each category displays size, count and risk note; the file list is expandable, paged, with checkboxes and "Open containing folder" (Explorer `/select`).
- [ ] Scan performs no writes (verified by test).
- [ ] Cancelling a scan stops within one entry and leaves no side effects.

### Stricter per-cache rules

The plan requires any rule stricter than the generic baseline to be documented here before it is enabled.

| Rule | Minimum age | Why stricter than 24 h |
|---|---|---|
| DirectX shader cache (`D3DSCache`) | >= 7 d | Entries are regenerated by games/GPU apps, so removing a recently used entry has a user-visible cost (slower first launch). Preferring older entries limits removal of the current working set. |
| Legacy web cache (`INetCache`) | >= 7 d | Holds cached content for legacy/IE-mode apps that is re-downloaded on demand. A longer window reduces the chance of removing content a running legacy component still references. |
| Crash dumps | >= 7 d | Recent dumps may be the user's only copy for a crash they are about to report or analyse. |
| Thumbnail / icon cache | >= 7 d | Explorer rebuilds these; a longer window avoids discarding recently active caches. |
| WER archive/queue | >= 14 d | Recent reports may not yet have been sent or reviewed by the user. |

Only `%TEMP%` uses 24 h. The ages are conservative judgement calls made for safety, not measured optima; the plan does not provide measurements behind them. They may be changed only through a documented edit here.

### C. Quarantine

Default mode for every cleanup. Files are moved, not deleted.

- Default location `%LOCALAPPDATA%\ClearPath\Quarantine`; alternative only if explicitly chosen by the user in Settings.
- Never auto-created at another drive root; never silently on another drive; never inside a rule root; never removable/network/UNC (`GetDriveType` = FIXED).
- Same volume => handle-based rename (file ID preserved). Different volume => transactional copy (policy: NTFS -> NTFS only; any ADS, EA, sparse/compressed/encrypted/reparse/offline attribute, or hard link => Skipped with reason).
- Original SHA-256 and size are computed through the validated share-none handle and journaled **before** any mutation.

Acceptance:
- [ ] Given a selected file, when quarantined, then journal state reaches `Quarantined` only after hash verification where applicable.
- [ ] Given same-volume quarantine, then file ID is preserved and recorded, and reported reclaimed bytes = 0.
- [ ] Given a file modified or replaced after scan (size/mtime/file ID mismatch), then it is Skipped("changed/replaced since scan").
- [ ] Given a file with `NumberOfLinks > 1`, then it is Skipped ("multiple hard links").
- [ ] Given insufficient space for a cross-volume item (size + 5 % margin), then it is Skipped before copying.
- [ ] Given a bit flip injected into a quarantine copy, then the item is never marked Quarantined, the original is kept, and the item is NeedsAttention.
- [ ] Given a second operation while one is active, then it is rejected (single-instance mutex + `active_operation` row).
- [ ] Given cancellation, then the current item finishes and remaining items are Skipped("cancelled").

### D. Restore

- Never overwrites. Existing destination => **Skip** (destination untouched) or **Keep both** (`name (restored N).ext`, N chosen so the name does not exist; final rename is no-replace so a race cannot overwrite).
- **No Replace option in MVP.**
- Missing parent directory is recreated only under the original approved root.
- Verified against the stored original SHA-256 before the item is marked Restored.

Acceptance:
- [ ] Given a restore with no conflict, then the file returns to its original path with matching hash.
- [ ] Given an existing destination and "Skip", then the destination is byte-identical with the same file ID afterwards.
- [ ] Given an existing destination and "Keep both", then the restored file has a non-existing `(restored N)` name and the existing file is unchanged.
- [ ] Given another process creates the destination between validation and rename, then no overwrite occurs (adversarial race test).
- [ ] Given a restore path outside an approved root, then restore is refused.
- [ ] UI offers only Skip and Keep both.

### E. History

- Lists operations (kind, mode, state, created/finished), their items, and per-item outcome/reason.
- Per-item actions: Restore, Purge (with confirmation).
- Items past retention show an **Expired** badge; retention never triggers purge.

Acceptance:
- [ ] Given no operations, then an empty state is shown (not sample data).
- [ ] Given an item is NeedsAttention, then Purge is unavailable for it.
- [ ] Given retention days elapse, then the item is badged Expired and a Safety Center notice appears; nothing is deleted.

### F. Purge (permanent delete from quarantine)

- Only from quarantine. Requires an **explicit irreversible confirmation**.
- Journal records authorization (timestamp, op ID, item list, confirmation text).
- Never initiated by recovery or retention. Ineligible: NeedsAttention, unresolved recovery, failed integrity.
- Documented exception to the "one verified copy always exists" invariant.

Acceptance:
- [ ] Given confirmation is not given, then nothing is deleted.
- [ ] Given a mix of eligible and ineligible items, then ineligible items are refused and the partial purge is reported item-by-item.
- [ ] Given a crash during `Purging`, then recovery never completes the purge on its own: bin present and hash ok => back to Quarantined; hash bad => NeedsAttention; absent => Purged.
- [ ] Purge result reports verified-deleted logical bytes and observed free-space change separately.

### G. Space accounting (report)

Reported separately: logical bytes quarantined; logical bytes permanently deleted (verified); bytes retained in quarantine; files skipped by reason; per-volume observed free-space change (before/after, after handles closed); discrepancy note labelled "observed - other processes may affect this".

Acceptance:
- [ ] Same-volume quarantine shows reclaimed = **0**.
- [ ] Purge shows logical vs observed separately.
- [ ] No figure is estimated or rounded up to look better.

### H. Safety Center

Shows: quarantine size / item count / expired count; pending recovery operations; last scan; privilege level (non-admin, from `WindowsIdentity` + manifest); handle-operation capability self-test result; exclusions; irreversible-operation warnings; manifest discrepancies with explicit "rebuild manifest" action.

Acceptance:
- [ ] Given recovery left NeedsAttention items, then they are listed with reason.
- [ ] Given the capability self-test fails, then scanning/cleaning is disabled with a visible reason (no path-based fallback).
- [ ] Given a corrupt/missing manifest, then it is reported and regenerated only on explicit user action after filesystem state is verified.

### I. Settings (Phase 2 subset)

Theme (dark/light, persisted); exclusions; retention days; quarantine location (validated per quarantine rules); log folder link.

Acceptance:
- [ ] Theme choice persists across restarts.
- [ ] A quarantine location overlapping a rule root, UNC, removable, or non-FIXED is rejected with a reason.
- [ ] Exclusions are honoured by PathGuard (excluded paths are never scanned or cleaned).
- [ ] No setting enables elevation, Replace-on-restore, automatic purge, or out-of-list cleaning.

### J. Crash recovery (startup)

Defined by the crash-point table in the plan (section 4.6); the full matrix is finalized in `15-safety-design.md`.

Acceptance:
- [ ] After `Process.Kill` at any point, relaunch leaves every file existing exactly once at its source or in quarantine with matching hash (CrashHarness).
- [ ] Any state not in the recovery table => everything preserved, NeedsAttention.
- [ ] Recovery never deletes the last verified copy; a corrupted copy is deleted only if another copy is independently verified against the original hash.
- [ ] A recovery banner and Safety Center list show unresolved items.

## Part 2 - Later modules (brief specs and constraints)

None of these is implemented in the MVP; each has an honest "Not available in this version" page.

| ID | Module | Brief | Safety constraints from the brief |
|---|---|---|---|
| C | Browser Privacy | Clear cache/history/cookies per installed browser, per-browser selection | **Never delete saved passwords**; no credential store access; browser must be closed or file skipped |
| D | Registry | Detect orphaned/invalid entries, report with explanations | **Opt-in only**; **`.reg` backup created before any change** and verified restorable; never automatic; never touch security/system hives broadly |
| E | Startup | List and enable/disable user startup entries with publisher info | **Never disable security services**; changes reversible; elevated entries shown read-only |
| F | Disk Analyzer | Size breakdown by folder/type | Read-only; same handle-based scanning rules; no deletion from this view |
| G | Duplicates | Find identical files within user-chosen folders | **SHA-256** content match (size prefilter only); **never auto-deleted**; user picks each; moves go through quarantine |
| H | Uninstaller | List installed apps; launch vendor uninstaller | Launch vendor-provided uninstall only; no forced removal of files/registry |
| I | Privacy Protection | Opt-in toggles for Windows privacy settings | Opt-in per setting; show current vs proposed; reversible; no silent system changes |
| J | Cookie Manager | View/keep/remove cookies by site | **Never delete passwords**; keep-list respected |
| K | AI Advisor | Explain scan results and suggest actions | **Advisory only**; cannot execute or approve actions; no auto-approve flag; user data sent off-device only with explicit consent; API keys never logged or stored in plain text |

Each later module requires its own spec, threat model update and safety review before implementation, and must reuse PathGuard / handle-based operations / quarantine for any file mutation.
